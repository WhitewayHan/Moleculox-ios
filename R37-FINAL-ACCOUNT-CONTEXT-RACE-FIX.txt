MOLECULOX iOS V8.5.77 — R37 FINAL ACCOUNT CONTEXT RACE FIX

WHY R37 EXISTS
An executable Apple-to-Google account-switch simulation exposed two remaining
context races in the supplied R36 package even though its string-presence tests
passed:

1. Manual Sync Now rechecked account context after the core progress save, but
   not after ranking cleanup/classic/duel awaits. An old Apple operation could
   therefore continue with the newly active Google profile and mark it saved.
2. cleanupOrphanRankingRows() fetched the Apple profile set and then compared
   leaderboard rows against the mutable global uid. If uid changed while the
   reads were pending, the function could build deletion requests for the new
   account using the old account's valid-profile set.

R37 CORRECTIONS
- Ranking cleanup captures {uid, authGeneration} after Firebase readiness.
- Profile paths, row ownership filters and deletion targets use captured ownerUid.
- Cleanup rechecks the captured account after every read, immediately before
  every delete batch, and after the batch completes.
- A stale cleanup resolves neutrally as cloud/account-context-changed.
- Placeholder ranking cleanup receives the same immutable-context protection.
- Manual Sync Now checks account/profile context after ready, reconciliation,
  core save, cleanup, classic ranking and duel ranking.
- Manual core/duel snapshots are deep-cloned and the original profileId is fixed
  for the complete operation.
- Stale manual errors do not write diagnostics or update the new account UI.
- Connectivity reconciliation captures context before Firebase readiness and
  ignores stale catch/status/diagnostic work.
